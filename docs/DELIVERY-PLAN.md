## 실행·리뷰 규칙

현재 채팅의 2시간 예약으로 이어간다. 조정자는 Backend·Frontend·Recommendation 전담
하위 에이전트를 사용하고 [세 영역 운영·README·지속 개선 기준](AUTOMATION-PLAYBOOK.md)을 따른다.
매 실행은 최신 사용자 지시, 연결된 비공개
기획의 작업 목록, 각 레포 AGENTS.md, docs/plans의 진행 계획, Git·PR·리뷰·CI를 확인한다.
기획 접근 실패를 작업 없음이나 전체 완료로 해석하지 않는다. 마지막 확인 계획에서
독립 작업을 진행할 수 있지만 확인하지 못한 기획 상태를 덮어쓰지 않는다.

진행 중 작업·리뷰 결함을 먼저 처리하고, 선행 기술 조건이 충족된 작은 작업을 실제로
구현한다. 과거 PR 리뷰 미확인이나 전체 체크리스트 미완료만으로 독립 작업을 막지 않는다.
계획·관찰·문서 수정만 반복하거나 변화 없이 빈 커밋을 만들지 않는다.

작업 전 앱의 활성 채팅·Git·ignored 체크포인트와 저장소별 `.pubburi/automation-lease/`를
함께 확인한다. Backend의 `scripts/automation_lease.py`로 원자적으로 소유권을 획득한다.

```bash
python3 scripts/automation_lease.py acquire --repo . --owner CURRENT_CHAT_ID
python3 scripts/automation_lease.py status --repo . --owner CURRENT_CHAT_ID
python3 scripts/automation_lease.py release --repo . --owner CURRENT_CHAT_ID
```

같은 checkout을 다른 살아 있는 작업이 사용하면 전환·stage·commit·push·빌드·동일 기획
항목 수정을 중복 실행하지 않는다. 잠금 시간만으로 소유권을 빼앗거나 kill/stash/reset하지 않는다.
기존 소유 작업이 종료됐는지 확인하고 근거를 남긴 뒤 재개한다. 사용자의 다른 채팅이나
외부 사람에게 메시지를 보내지 않는다. 현 채팅의 전담 하위 에이전트 협업 도구 통신은 허용한다.

main에 직접 쓰지 않고 Conventional Commit과 작업 브랜치·PR을 사용한다. **최신 head의
필수 CI·Codex 리뷰·관련 수동 검증이 끝나고 구체적 미해결 지적이 없을 때만 Squash merge**한다.
리뷰 요청과 한국어 수정 답글은 승인된 범위다. 리뷰의 대기·오류·쿼터 제한을 승인으로 보지 않는다.
리뷰 연결 설정이 없으면 정확한 설정 필요 사항을 기록하고 다른 독립 작업을 계속한다.
기존 보호 규칙을 완화하거나 리뷰를 임의 승인·기각·삭제하지 않는다.

지적을 수정·검증한 뒤 원래 스레드에 수정 커밋·검증 근거를 답글로 남기고 native conversation을
해결한다. 직전 최신 스레드를 다시 확인해 중복 답글을 피한다. outdated 표시는 해결 근거가 아니다.
PR·head SHA·review ID·thread/comment ID·처리 상태는 ignored 체크포인트에 저장한다.
병합 후 실제 merge 기록·main CI를 확인하고 main을 ff-only로 동기화한다. 추가 변경이 없는
병합 브랜치만 정리한다. 무관한 PR은 병합하지 않는다.

## 데이터·완료 근거

인증·업무 데이터·이벤트 저장은 Backend가, 특성 처리·추천 계산·이유는 Recommendation이 담당한다.
기존 /api·ApiResponse·세션 계약과 GET /health를 보존하고 새 계약은 OpenAPI·테스트와 함께 관리한다.
콘텐츠 기반 추천부터 만들며 신규 사용자·데이터 부족·추천 서버 지연·장애의 대체 응답을 검증한다.

데이터 출처·라이선스·누락·분리 방법을 기록하고 공개 데이터 실험과 서비스 카탈로그 평가를
구분한다. 합성 로그는 기능 검증용이며 실제 사용자 선호나 추천 품질의 증거가 아니다.
학습·검증·최종 평가를 분리하고 기준 모델과 비교한 지표·규모·조건·한계를 남긴다.
수집 전에 항목별 이용 조건·추가 유의사항·이미지/원문/재배포/학습 범위를 확인한다.
현재는 비상업 사이드 프로젝트이며 상업적 이용 전 협의 조건만으로 비상업 이용을 차단하지 않는다.
이용 조건이 충돌하거나 불명확한 원천은 보류하고 허용된 소규모 카탈로그로 독립 작업을 진행한다.
기존 시드·이미지도 이용 권리가 검증됐다고 가정하지 않는다. 실제 사용자 학습 데이터가
부족하면 AI03의 차단·한계를 기록하며 공개 와인 품질 예측 실험으로 추천 성과를 대체하지 않는다.

성능 개선은 변경 전 병목·가설·지표·기준 커밋·동일 입력/환경·캐시·워밍업·반복 횟수를
정하고 실측한다. 변경 후 원값·표본 수·중앙값·분포·절대 차이·개선율·누락·편차를 기록한다.
0 기준값의 상대 개선율은 계산하지 않는다. 잡음 수준 차이나 테스트 개수·CI 시간으로
서비스 성능 향상을 주장하지 않는다. 성능과 무관한 문서 변경에는 불필요한 측정을 강제하지 않는다.

기획은 작업 ID·우선순위·목표일·선행 조건·완료 기준·상태·PR/실행 근거로 관리한다.
계획·구현·검증·병합을 구분하고 관찰한 근거가 있는 항목만 완료 처리한다.
README는 현재 기능과 기술 중심으로 쓴다. 후속·계승 프로젝트 소개는 넣지 않는다.
Backend·Recommendation에는 스크린샷 항목이나 준비 중 문구를 넣지 않는다.
Frontend는 검증한 실제 화면만 추가한다. 각 README는 실제 문제 해결 사례 정확히 네 개를
목표로 근거를 확보하고 더 강한 사례로 교체한다. 사례·수치·학습 결과를 만들어내지 않는다.
관련 프로젝트·개발자·기획 링크 모음은 README에 재추가하지 않는다.
기획 완료 후에도 기한까지 각 담당이 기존 기능의 오류·최적화 기회를 찾아 재현·측정·수정한다.
개인 경로·자격정보·원문 로컬 로그·비공개 기획 주소는 공개 근거에 추가하지 않는다.
