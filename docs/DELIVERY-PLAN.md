# Pubburi 백엔드 개발·운영 기준

이 문서는 Backend의 업무 API·DB·인증·검색 연동을 다룬다. 전체 기능·담당·진척은 승인된 공통 기획,
각 영역의 코드·설계·테스트·상세 계획·문서·PR은 소유 레포에서 관리한다.

- Backend: 회원/권한·세션, 상품/주문/후기/취향/찜/장바구니/기록/알림 API, PostgreSQL/JPA 전환·업무 DB, 검색 색인 동기화·API·대체 응답.
- Frontend: 화면·라우팅·상태·API 소비·브라우저·정적 자산. [Frontend 지침](https://github.com/Pubburi/Frontend/blob/main/AGENTS.md)이 해당 영역 기준이다.
- Recommendation: 원천 조사/수집·정제·검수 카탈로그·특성·모델 학습·점수/이유·평가. [데이터·모델 계획](https://github.com/Pubburi/Recommendation/blob/main/docs/DATA-AND-MODEL-PLAN.md)이 정본이다.

추천 모델·실험 계획을 Backend에 복제하지 않는다. 업무 DB/API는 추천 영역의 검수 카탈로그/특성
산출물과 버전 계약으로 연동한다. 공통 API 명세는 제공자가 소유하고 소비자는 참조한다.

## 범위와 일정

기한은 **2027-02-05 23:59:59 Asia/Seoul**이다. 2027-02-06 00:00부터 새 구현·커밋·병합을
하지 않고 변경·미완료·차단·마지막 검증·PR 상태를 인계한다. 장시간 실행과 커밋·병합 직전에도 시각을 확인한다.

R01–R08·F01–F12 **20개 필수 기능**과 P1/P2 구현 순서를 유지한다. Backend는 해당 기능의
업무 데이터·인증·API·연동을 담당하며 웹 UI·추천 알고리즘의 상세와 완료 근거는 각각 소유 레포에 둔다.
챗봇·모바일 구현/테스트/배포/레포 운영·실제 결제/배송은 제외한다. 모바일 공통 API 호환성만 유지한다.
AWS는 후속 사용자 지시 전까지 연결하지 않고 [로컬 개발](LOCAL-DEVELOPMENT.md)을 따른다.

DB02 일부이며 현재 API/JPA·전체 데이터 복사·relay·cutover 완료와 구분한다.

## 검색·추천 연동

[검색 계획](SEARCH-PLAN.md)의 Backend 담당 S01–S05를 구현한다. OpenSearch는 로컬 Docker의
파생 색인이며 목표 업무 정본은 PostgreSQL이다. 현재 MySQL 정본은 안전한 이관 전까지 보존한다.
변경/삭제·재처리·재색인·필수 조건·페이지/정렬·대체 검색을 PostgreSQL에서 별도로 검증한다.
Java17·Spring·/api·ApiResponse·세션과 추천 계약을 보존하며 MyBatis/MySQL 최종 runtime은 DB03에서 제거한다.
Backend는 추천 요청의 인증·업무 맥락·최신 상품 유효성·시간 제한·장애 대체를 담당한다.
추천 계산·데이터/모델·학습·평가는 Recommendation 정본을 참조한다.
자유 문장 의미/벡터 검색·Jira·그래프는 별도 검토이며 자동으로 범위를 늘리지 않는다.

## 작업 소유권·실행

현재 채팅의 2시간 예약과 조정자/세 영역 에이전트를 유지한다. [운영 경계](AUTOMATION-PLAYBOOK.md)를
따르고 최신 지시·승인 기획·자기 레포 AGENTS·진행 계획·Git/PR/CI를 확인한다.
기획 접근 실패를 전체 완료로 보지 않고 마지막 확인 계획의 독립 작업을 진행한다.

작업 전에 활성 채팅·Git·ignored 체크포인트·`.pubburi/automation-lease/`를 확인하고
`scripts/automation_lease.py`로 소유권을 원자적으로 획득한다. 조정자는 담당/파일/Git 소유자를
기록하고 동일 파일·index·브랜치를 동시 수정하지 않는다. 살아 있는 소유권을 시간 만료만으로
빼앗거나 kill/stash/reset하지 않는다. 종료 작업은 실제 종료·Git/프로세스 근거를 확인한 뒤 재개한다.
사용자 변경·다른 작업자의 프로세스·미병합 브랜치를 보존한다. 다른 사용자 채팅·외부 사람에게
메시지를 보내지 않고 현 채팅 하위 에이전트 협업은 허용한다. 기존 권한·비용·외부 연락 경계는 유지한다.

진행 구현·구체적 리뷰 결함·필수 Backend 작업을 우선하고 다른 영역 전체의 대기로 독립 작업을 막지 않는다.
기획 완료 후에도 기한까지 정합성·보안·쿼리·동시성·복구 결함을 재현·측정·수정한다.
근거 없는 리팩터링·반복 문서·빈 커밋은 만들지 않는다.

## 검증·리뷰·인계

main에 직접 쓰지 않고 Conventional Commit과 작업 브랜치·PR을 사용한다.
**최신 head의 필수 CI·완료된 Codex 리뷰·관련 검증·미해결 지적 없음**을 확인한 뒤 Squash merge한다.
대기·실패·쿼터 제한은 승인이 아니며 보호 규칙을 완화하거나 리뷰를 임의 승인·기각·삭제하지 않는다.
구체적 지적은 수정·검증 후 원래 스레드를 읽고 한국어 커밋/검증 답글과 native conversation 해결을 처리한다.
outdated만으로 해결을 추정하지 않고 중복 답글을 피한다. PR/head/review/thread/comment ID·상태는
ignored 체크포인트에 기록한다. 병합 기록·main CI를 확인하고 ff-only 동기화한 뒤
추가 변경이 없는 병합 브랜치를 원격/로컬 모두 삭제한다.

검증 조건·원값·실패·한계를 기록한다. 성능은 변경 전 병목·가설·기준 커밋·입력/환경·캐시·워밍업·반복을
정해 실측하고 같은 조건의 변경 후 분포·절대 차이·개선율을 남긴다. 0 기준값·잡음·테스트 수·CI 시간으로
서비스 성능을 만들지 않으며 문서 변경에 무관한 측정을 강제하지 않는다.

실사용자가 없는 비상업 프로젝트이며 시연 계정/가격/주문을 실제 인기·구매 성과로 표시하지 않는다.
업무 데이터·권한·개인정보·보관/삭제의 성격을 보존한다. 추천 학습은 사용자 축적을 기다리지 않는
Recommendation 계획에 따른다. 데이터/모델의 상세 판단과 실험은 추천 레포에서 수행한다.

Backend README는 현재 기능·기술과 실제 사례 네 개를 목표로 관리한다. 더 강한 실제 사례가
있을 때만 교체하고 없으면 유지한다. 스크린샷·준비 중·후속 프로젝트 소개·관련 프로젝트/개발자/기획
링크 모음을 넣지 않는다. 검증 근거는 계획·PR·CI에 남긴다. 개인 경로·자격정보·로컬 원문 로그·
비공개 기획 주소는 공개 근거에 포함하지 않는다.
