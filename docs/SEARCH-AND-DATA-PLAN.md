# 검색엔진·주류 데이터·추천 학습 계획

2026-10-31 사용자 승인에 따른 **구현 계획**이다. 검색엔진 설치·색인·데이터 수집·학습을
완료했다는 문서가 아니다. 기존 2027-02-05 기한과 로컬 개발·세 영역 담당·PR 게이트를 유지한다.
S/DAT는 F02·R06·R02·F03·AI01–04의 기술 작업이며 R 8개 + F 12개 = 20개 기능과 중복 합산하지 않는다.
서비스는 사용자 지시에 따라 **비상업 사이드 프로젝트**로 기획한다. 상업적 이용 전 협의 조건만으로
현재 비상업 이용을 차단하지 않는다. 다만 공개 웹 데모·학습·원본 재배포·이미지/원문은 항목별 조건을 확인한다.
향후 상업적 이용으로 전환하면 데이터 이용 범위를 다시 검토한다.
최신 확정 조건은 **외부 사용자 없음·행동 데이터 축적 없음**이다. 명시 취향·상품 맥락으로
개인화하고 카탈로그만으로 모델을 개발한다. 사용자 모집·미래 로그·외부 평가자 확보는 선행 조건이 아니다.
원천·수집 범위·정제/특성·모델·튜닝·평가·채택은 에이전트가 근거를 남기며 자율 결정해 실행한다.
조건이 맞지 않는 원천이나 알고리즘은 대안으로 바꾸고 실제 차단만 보고한다. 기존 비용·계정/외부 연락 경계는 유지한다.

## 검색 범위와 책임

- Backend는 MySQL 원본·상품 변경·색인 동기화·검색 API·인증·장애 복구를 담당한다.
- Frontend는 React 검색 화면·자동완성·필터·URL 상태·최신 요청 반영과 추천 이유를 담당한다.
- Recommendation은 허용된 후보의 취향 점수·이유와 평가를 담당한다. 필수 조건을 벗어난 상품을 추가하지 않는다.
- OpenSearch는 AWS 서비스가 아닌 로컬 Docker로 실행한다. 구현 시 엔진/한국어 플러그인 버전을 맞춰 고정한다.
- `/api`·ApiResponse·세션과 기존 페이지/정렬 계약을 보존한다. MySQL이 원본이고 색인은 재생 가능한 파생 데이터다.
- 현재 상품에는 name/type/price/abv/img/order_count가 있다. 맛·향·설명·용량 검색은 F03에서 출처 검수한 필드에만 적용한다.
- 자동완성·한국어 분석·검수 동의어·제한된 오타 허용을 각각 검증한다. 형태소 분석만으로 초성/로마자/모든 오타가 해결됐다고 하지 않는다.
- 자유 문장의 의미 해석·벡터/LLM 검색은 이번 범위에 자동 포함하지 않는다. R06은 선택한 문구를 명시적 검색 조건으로 연결한다.

## 데이터 수집 원칙

우선순위는 **이용 범위를 확인한 API/다운로드 → 제공 허락을 받은 자료 → 직접 작성/측정한 자료**다.
웹에 공개됐거나 robots.txt가 허용한다는 사실만으로 재사용·학습·재배포 권리를 승인하지 않는다.
약관·라이선스·추가 유의사항·호출 제한을 함께 확인한다. 로그인/차단 우회와 무단 대량 수집,
상점/블로그 후기·작성자 계정 수집을 기본 전략으로 삼지 않는다. 외부 문의 발송은 별도 사용자 지시를 따른다.

원천마다 URL·제공자·확인일·버전/해시·허용 목적(표시/검색색인/학습/공개 재배포)·출처 표시·
변경 표시·이미지 조건·요청량·삭제/수정 대응을 기록한다. 충돌/미확인은 보류하며 다음 수집원으로 우회한다.
API 키는 로컬 환경변수로 관리한다. 원본 데이터·모델·권한 없는 이미지·원문·실사용 로그는 Git에 올리지 않는다.
재현 가능한 수집 명령·명세·권리 기록과 직접 만든 작은 테스트 fixture만 추적한다.
기존 시드·정적 이미지 역시 출처/사용 허락이 확인됐다고 가정하지 않고 감사한다.

## 추천 모델을 개발하는 순서

**AI03은 사용자 없이 가능한 카탈로그 기반 학습·비교로 확정한다.** 협업 필터링·행동 기반
선호 학습은 현재 개발의 필수 경로로 채택하지 않는다. 데이터 권리·필드/규모 감사 뒤 다음 모델을 비교한다.

| 구분 | 학습·점수 | 비교·채택 기준 |
|---|---|---|
| B0 기본 기준선 | 필수/제외 조건을 적용한 결정적 기본순 | 신규 취향·빈 데이터·장애에서 재현 가능한 기본 동작. 시드 order_count를 실제 인기 통계로 해석하지 않음 |
| B1 기본 서비스 모델 | 검수 주종/태그·허용된 텍스트의 TF-IDF vocabulary/IDF와 수치 특성 변환을 카탈로그에 실제 fit. 입력 취향·선택 상품과 유사도 계산 | 특성/누락/스케일/가중치 근거를 버전 관리. 필수/제외 조건을 먼저 적용하고 추천 이유는 실제 사용 특성과 일치 |
| M1 표현 학습 후보 | 차원·제품 다양성이 충분하면 TF-IDF + TruncatedSVD 등 비지도 카탈로그 표현 학습을 실제 비교 | 표본/차원/rank를 확인해 구성 선택. 크기/정보 보존/관련성/지연을 B1과 비교하고 유용할 때만 운영 채택. 작은 데이터에 억지로 적용하지 않음 |

TF-IDF의 학습은 카탈로그의 어휘/빈도 특성을 맞추는 것이며 사용자 선호 학습이 아니다.
검색엔진 색인 생성과도 구분한다. B1의 실제 fit·기준선 비교·보고서는 필수다. M1은 적합성
검토와 근거 있는 채택/미채택을 요구하며, 복잡한 모델의 운영 채택 자체를 성공 기준으로 두지 않는다.
유효한 실험 없이 문서상의 선택만으로 학습 완료 처리하지 않는다. 표본이 부족하면 허용 카탈로그를
확대하거나 표현을 단순화해 실행하고 실제 권리/데이터 차단을 기록한다.

## 사용자 없는 기능·평가

- R02는 현재 입력한 명시 취향으로 즉시 개인화한다. R03은 상품 특성 유사도, R04는 실제 근거,
  R05는 입력 피드백의 순위/제외 반영, R07은 장바구니/데모 주문의 상품 특성·검수 규칙,
  R08은 유사성과 속성 다양성을 함께 고려한다. 모든 R/F 기능은 시연 계정으로 저장·권한·복구까지 검증한다.
- 연관 후보를 함께 많이 구매한 통계로 표시하지 않는다. 실제 선호 데이터 없이 인기·CTR·전환율·
  사람의 만족도·취향 적중률을 성과로 쓰지 않는다. 시연 가격과 기록의 성격을 유지한다.
- 프로필/장바구니/찜/평점/관심 없음의 시나리오 입력과 합성 행동은 선언형 기능 시험 조건이다.
  실제 고객을 대체한 선호 정답이 아니다. 학습을 위해 가짜 클릭/평점을 대량 생성할 필요가 없다.
  계정 식별/개인정보·권한·보관/삭제 계약은 기능상 유지하되 로그 축적을 기다리지 않는다.

평가는 세 층을 구분한다.

1. **필수 기능·정합성:** 독립 검사기로 가격/도수/주종 조건·제외·중복·링크·추천 이유·누락/상충 조건·
   신규 프로필·장애 fallback을 검증한다. 필수 조건 위반과 제외 상품 재노출은 없어야 한다.
2. **카탈로그 관련성:** 튜닝 전에 고정한 질의/프로필 명세와 확인 가능한 상품 사실로 관련성을 평가한다.
   추천 점수 함수로 정답을 다시 만들지 않는다. AI 초안의 라벨도 출처 사실과 추정을 구분해 검수하고
   확인 불가능한 맛/향을 정답에서 제외한다. 독립 관련성 라벨이 있을 때만 Recall/NDCG를 산출하고
   '카탈로그 시나리오 관련성'으로 명명한다. 단순 필터 통과율은 조건 검증이며 개인 취향 정답이 아니다.
3. **표현·운영:** 카탈로그 커버리지·속성 다양성·누락/변형 안정성과 고정 조건의 지연/메모리·재현성을 비교한다.
   재구성 오차/설명분산은 표현 정보 보존 지표이며 사람의 선호 품질로 환산하지 않는다.

**고정 카탈로그 평가**는 알려진 전체 카탈로그를 표현/색인에 사용했는지 밝히고 개발/검증/최종
시나리오를 분리해 최종 명세를 고정한다. **신규 상품 일반화**는 동일 제품/용량·도수 변형을
그룹으로 묶어 학습/검증/최종 평가를 나누고 어휘·스케일·차원 축소를 학습 부분에만 fit한다.
두 결과를 혼용하지 않는다. 실제 시계열/사용자 데이터가 없는 상황에 시간·사용자 분리를 꾸미지 않는다.
동일 후보·필터·K·카탈로그 버전으로 B0/B1/적합한 M1을 비교하고 원값·실패·분리·한계·선택 근거를 남긴다.
관련성 라벨이 없으면 그 지표는 미산출 사유와 대체 검증을 기록하며 AI03 전체를 사용자 부재로 대기시키지 않는다.
UCI 품질 예측은 선택적 별도 실험이며 카탈로그 추천 학습/평가 완료를 대신하지 않는다.
