# 전담 에이전트·대표 사례·지속 개선 지침

- 범위: 단일 2시간 예약의 Backend/Frontend/Recommendation 전담 하위 에이전트 운영, 소유권·공통 검증 경계, README 사례 선정/교체와 기획 완료 뒤의 지속 개선.
- README에서 관련 프로젝트·개발자·기획/출처 링크 모음·모바일 소개와 목차/앵커를 제거한다. 출처 문서 자체는 보존한다.
- 매 실행 사례를 비교하되, 채용 관점에서 더 강한 실제 문제 해결이 발견됐을 때만 교체한다. 영향·원인 근거·상태/데이터 난도·대안과 판단·실제 기여·재현 결과를 비교하고 더 강한 근거가 없으면 보존한다.
- Backend와 Frontend는 현재 소스·기존 근거에 기반한 독립 사례를 각각 네 개 작성했다. Recommendation은 헬스 계약만 구현돼 독립 사례가 한 개다. 부족한 세 개는 필수 조건·fallback·누수 없는 평가의 실제 구현/검증 과제로 추적하며 성과를 꾸미지 않는다.
- 각 worker는 자기 README와 사례 등록부만 편집했고, 조정자는 AGENTS·공통 정책·Notion·예약·Git/PR을 담당했다. 동일 파일과 index/branch의 동시 쓰기를 하지 않았다.
- 정적 확인: 사례의 여섯 항목 순서·목차 앵커·제거 대상 부재·현재 소스와 코드 발췌 일치·저장소 비밀정보/생성물 검사·diff 공백 검사를 수행한다. 기존 실행 근거와 이번 문서 검증을 구분한다.
- 필수 CI와 최신 head Codex 리뷰·미해결 지적 없음 후 각 PR을 Squash merge하고 main CI·ff-only 동기화·원격/로컬 작업 브랜치 삭제를 확인한다. 현재는 PR 검증 전이다.
- 이 변경은 문서·운영 지침 변경이며 앱 실행 성능과 무관하다. 성능 수치를 새로 만들거나 테스트 개수·audit 항목 감소를 성능 개선으로 표시하지 않는다.
