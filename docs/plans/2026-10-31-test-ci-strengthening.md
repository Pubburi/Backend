# Backend HTTP·DB 회귀 검증 보강

- 기존 CI는 MySQL 시드·상품 GET 기동과 가짜 DAO 기반 단위 테스트를 실행했다.
- 패키징한 실제 jar의 세션·권한·JSON 검증 계약과 성공 주문/실패 주문의 DB 상태 불변을 추가한다.
- 기존 포트를 점유한 서버를 잘못 검증하지 않게 시작 전 점유 검사와 새 jar PID/시작 로그를 확인한다.
- DB 쓰기는 전용 `*_ci` 스키마·loopback·컨테이너 포트·실행 marker와 명시 opt-in을 모두 확인한 경우에만 허용한다.
- 현재 주문 서비스의 헤더/상품 UPDATE 이후 missing-product 예외 경로를 검증하며 실제 결제·단가/삭제 이력·전체 동시성 기능을 구현했다고 표시하지 않는다.
- 검증 결과는 PR/CI 및 ignored 실행 기록에 남긴다. 이번 테스트/CI 보강을 앱 성능 개선 수치로 사용하지 않는다.
- Java 17 단위 테스트·패키징과 전용 폐기 MySQL의 실제 HTTP/쓰기 후 실패 rollback을 로컬에서 확인했다. 기본 sandbox의 ps/socket 제한은 실행 권한을 갖춘 검증에서 재실행해 통과했으며 제품 결함으로 집계하지 않는다.
