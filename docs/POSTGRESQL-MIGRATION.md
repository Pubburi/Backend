# PostgreSQL·JPA 전환 계약

2026-11-01 사용자 결정에 따라 목표는 **PostgreSQL18.6 + Spring Data JPA(Hibernate) +
Flyway Community**, Python relay는 **Psycopg3**다. MyBatis 대체 기술 선정은 끝났으며 다시
선택 대기로 두지 않는다. 기본 Maven JAR은 PG/JPA이며 MySQL/MyBatis는 명시 baseline과 이관 전 원본으로 보존한다.
DB01–DB06은 기존 필수20기능의 기술 선행 조건이지 추가 사용자 기능이 아니다.

## 일정과 완료 경계

DB/React 전환과 기능 보존 재인수의 2026-11-22 목표를 유지한다. 12월13일 P1,
12월14–31일 P2를 거쳐 전체20개 MVP의 구현·연결·필수 검증을 2026-12-31 Asia/Seoul까지
마친다. DB03의 남은 실제 DAO/API·DB04의 거래/계정/권한·DB05 Psycopg3/검색 fallback·
DB06 실제 전환/rollback과 세 서버 필수 회귀는 MVP를 위한 선행/완료 조건이며 1월로 미루지 않는다.
현재 부분 제공자나 fixture 성공을 전체 DB03–06·main 전환·MVP 완료로 세지 않는다.

2027-01-01부터는 추가 튜닝·실측 최적화·신뢰성 강화·확대 회귀·최종 인수/문서를 진행한다.
남은 필수 기능과 기술 선행·필수 결함을 독립 리팩터링/선택 최적화보다 우선한다.
최종2027-02-05와 2027-02-06 00:00 Asia/Seoul 구현·커밋·병합 중단은 유지한다.
자세한 판정은 [일정 변경 기록](https://github.com/Pubburi/Backend/blob/9033935f209df82a6b3dac351762c23ca1359887/docs/plans/2026-11-03-mvp-deadline.md)을 따른다.

## ADR — 실행 계층과 스키마 책임

- 일반 CRUD/관계는 JPA Repository, 읽기는 DTO projection·JPQL/Criteria를 사용한다. 원자 갱신·
  upsert·queue/잠금은 JPA native query/EntityManager로 의미를 통제한다. 서비스 TX/배치 조회를
  유지하고 엔티티를 HTTP에 직접 노출하지 않는다. OSIV는 끄고 Hibernate ddl-auto=validate를 쓴다.
- PostgreSQL 전용 versioned Flyway SQL이 스키마 정본이다. 기존 MySQL001–008이나 data.sql을
  PostgreSQL 문법으로 덮어쓰지 않는다. 새 설치·복사 이관·런타임 cutover는 각각 검증한다.
- DB02는 독립 `tools/postgresql-migration`의 실제 스키마 installer/검증과 [원본 snapshot export](SOURCE-SNAPSHOT.md) 및
  [승인 snapshot의 빈 target 복사/검증](SOURCE-IMPORT.md)를 제공한다. 이 단계는 root POM/API를
  바꾸지 않았다. 현재 DB03은 그 [실제 JPA 제공자](JPA-REHEARSAL.md)를 root `src/main`과 기본
  `pom.xml`로 승격했다. `tools/mysql-baseline/pom.xml`은 기존 MySQL 런타임/회귀를 명시 빌드한다. 미제공 API는 등록하지 않으며 비사용 entity/stub로 전체 전환을 주장하지 않는다.
- Java17과 기존 MySQL baseline의 Boot3.5.0을 보존한다. 기존 BOM의 Hibernate6.6.15.Final/JDBC42.7.5를 확인했다.
  독립 도구는 Flyway OSS13.12.0 + PostgreSQL plugin13.12.0과 보안 수정된 JDBC42.7.14를 고정한다.
  기본 JPA 제공자는 Boot3.5.16/Spring Data JPA3.5.13/Hibernate6.6.53.Final과 실제 기동을
  검증한다. 기본 JAR 승격과 실제 DB/launcher 선택·전체 전환 상태는 구분한다.

근거: [Flyway13.12.0](https://github.com/flyway/flyway/releases/tag/flyway-13.12.0),
[Java17/14부터 Java21](https://documentation.red-gate.com/fd/api-java-277579358.html),
[PostgreSQL18/plugin](https://documentation.red-gate.com/fd/postgresql-database-277579325.html),
[pgJDBC42.7.14 보안 수정](https://github.com/pgjdbc/pgjdbc/releases),
[PostgreSQL18.6](https://www.postgresql.org/docs/18/release-18-6.html).

검증/CI 이미지는 `postgres:18.6@sha256:3a4264520e121176619f54ff867d12774bc81e95e7b84db58d63bccdb6144b81`로
고정한다. OCI index에 linux/amd64·linux/arm64/v8가 포함됨을 확인했으며
[공식 이미지 소스](https://github.com/docker-library/postgres/tree/e00e1bd34ec5c8a8e7ad89b273b3d42efaf6d5bc/18/trixie)를 따른다.

## 타입·기존 값 보존

`pubburi` schema에 현재16업무표를 정의한다. Flyway history도 이 schema에 두며 검증용 marker는
별도 public schema다. 초기 SQL은 사용자/상품/epoch/source UUID·ACK를 생성하거나 재설정하지
않는다. 실제 복사 또는 새 runtime의 명시 초기화가 이 값의 수명을 정해야 한다.

| 경계 | PostgreSQL 표현과 보존 기준 |
|---|---|
| PK·새 ID | integer/bigint GENERATED BY DEFAULT AS IDENTITY + PK. 명시 ID를 넣고 원본 next watermark를 별도로 보존 |
| 금액/주문 이력 | integer 단가·합계·총액/스냅샷 필드 그대로. nullable 상품/회원 FK의 SET NULL과 자식 CASCADE 분리 |
| epoch·source·claim | UUID. 원본 canonical 값 검수 후 그대로 이관하며 임의 새 UUID로 대체하지 않음 |
| 도수/후기 소수 | 기존 FLOAT의 단정도는 REAL, 좌표 DOUBLE은 double precision. 5.555를 두 자리로 반올림하지 않음 |
| 취향 숫자 | numeric(5,2), unknown NULL/검수[]의 known 플래그와 별도 값 관계 보존 |
| 시각 | timestamp(6) with time zone, 연결 UTC. 원본 시각의 timezone/소수 정밀도를 확인한 뒤 이관 |
| 불변 event | json으로 받은 원문·공백·키 순서를 보존. jsonb 재직렬화로 같은 버전의 본문을 재생성하지 않음 |
| 문자열 비교 | ID/업무 name/type은 명시 ICU und-u-ks-level1, canonical 태그/구분 값은 C. 원문 값은 변경하지 않음 |

[json의 원문 보존](https://www.postgresql.org/docs/18/datatype-json.html)과
[identity 동작](https://www.postgresql.org/docs/18/ddl-identity-columns.html)을 따른다.
ICU는 MySQL0900_ai_ci와 모든 Unicode/정렬이 같다는 보장이 아니다. 고정한 대소문자·악센트·
한글 조건을 먼저 검증하고 실제 원본의 충돌·질의/정렬 기대값을 별도로 대조한다. 비교 불일치를
조용히 병합/정규화하지 않는다. 그 대조가 끝나기 전 전체 DB02/검색 동등성을 완료로 표시하지 않는다.
PostgreSQL18의 [nondeterministic LIKE](https://www.postgresql.org/docs/18/functions-matching.html)와
[collation 전제](https://www.postgresql.org/docs/18/collation.html)를 확인한다.

실제 이관 전 source의 SHOW INDEX를 읽기 전용으로 대조했다. PostgreSQL FK가 supporting index를
자동 생성한다고 가정하지 않고 원본 PK16·추가 unique1·nonunique13의 키를 보존한다.
[정규화 계약](../tools/postgresql-migration/src/main/resources/source-index-contract.tsv)은 표/유일성·
키 순서/방향·nullable 키의 NULL 순서만 포함하며 업무 row나 원문 로그는 아니다. migrate/validate는
실제 pg_index의 valid/ready·비partial·비expression BTREE를 대조한다. 기존 조회 index와 FK 지원
index를 누락하지 않으며 새 성능 수치를 만들거나 불필요한 index를 추가하지 않는다. source에서
확인한 nullable ASC의 NULL-first는 명시하며 실제 질의의 NULL 정렬 이식은 DB03에서 재검증한다.

## 명시 installer — 폐기 복사 전용

Java17에서 다음과 같이 독립 도구를 빌드한다. 기존 API의 기동/의존성과 분리된다.

~~~bash
./mvnw --batch-mode --no-transfer-progress -f tools/postgresql-migration/pom.xml verify
python3 scripts/postgresql_schema.py migrate
python3 scripts/postgresql_schema.py validate
~~~

명령은 설정된 `*_ci` 로컬 PostgreSQL18.6 UTF8 검증 DB에만 허용한다. wrapper는 명시 CID의
pubburi.validation label·Running·5432/tcp의 정확한 loopback 공개 포트를 확인한다. Java 도구는
실제 DB명/버전·실행별 public.pubburi_pg_migration_guard token·TLS·비superuser를 확인한 뒤
Flyway를 호출한다. TLS verify-full·명시 공개 CA/SAN·SCRAM을 요구하고 비밀번호는 환경에서만
읽는다. 외부 URL/query/userinfo·implicit mutation·clean/baseline/repair는 제공하지 않는다.
예시 환경은 [도구 환경 예시](../tools/postgresql-migration/.env.example)를 따른다. `.env`/CA/
실제 manifest는 ignored에만 보관하고 CA private key를 가져오거나 artifact에 넣지 않는다.

Flyway는 checksum을 검증하며 이미 설치한 V1은 다시 쓰지 않는다. 미추적 기존 schema를
baseline으로 조용히 채택하지 않는다. 실패한 transactional DDL의 부분 표를 확인하고 원인을
해결한 뒤 같은 migration을 재실행하며 repair/검사 생략으로 성공 상태를 만들지 않는다.

## 원본 next ID 예약

명시 ID 복사만으로 identity sequence가 따라오지 않는다. 살아 있는 행의 MAX+1만 쓰면 원본에서
삭제된 ID를 재사용할 수 있으므로 원본 AUTO_INCREMENT의 다음 값도 읽기 전용으로 수집해야 한다.
원본의 실제 읽기 전용 export와 고수위 검수는 [별도 도구](SOURCE-SNAPSHOT.md)로 제공한다. 다음
[import 도구](SOURCE-IMPORT.md)는 승인 snapshot의16표 전체 복사·전행 대조와7개 예약을 같은
TX로 연결한다. 다음 manifest는 별도 수동 예약 명령의 형식이며 import 뒤 자동으로 중복 실행하지 않는다.

~~~text
pubburi-identities-v1
t_product=9001
t_order=501
t_order_detail=601
t_comment=701
t_stamp=801
t_market=901
t_product_search_outbox=1001
~~~

위 숫자는 authored 예시이며 실제 source watermark가 아니다. 7개를 빠짐/중복/미지정 키 없이
양수 범위로 명시해 ignored 파일에 둔다. PUBBURI_PG_IDENTITY_FILE로 지정하고 다음을 실행한다.

~~~bash
python3 scripts/postgresql_schema.py reserve-identities
~~~

쓰기/relay를 중단한 상태에서만 실행한다. 도구는 소유 표 잠금을 잡고 모든 입력을 먼저 확인한다.
예약은 현존 PK와 삭제 후 남은 상품 version ID보다 커야 한다. target sequence를 뒤로 옮기지
않고 고정된7개 sequence에 transactional ALTER SEQUENCE RESTART를 적용한다.
[setval/nextval은 rollback되지 않지만](https://www.postgresql.org/docs/18/functions-sequence.html)
[ALTER RESTART는 transactional](https://www.postgresql.org/docs/18/sql-altersequence.html)이다.
이는 gapless ID 보장이 아니며 관리자 직접 sequence 변경/구 앱 혼용을 자동 통제하는 기능도 아니다.

## 현재 제공과 남은 전환

DB02의 [source 추출](SOURCE-SNAPSHOT.md)·[승인 import](SOURCE-IMPORT.md)는16표 전체 값/PK·
7개 고수위·UUID/epoch·원문 JSON/receipt를 검수한다. DB03의 [기본 JPA 제공자](JPA-REHEARSAL.md)는
53경로/67작업과 거래/계정 수명·취향/찜·기존 추천 caller를 제공한다. [로컬 실행](LOCAL-DEVELOPMENT.md)은
완료 release를 준비된 소유 copied PG에 연결하며 schema/역할을 만들거나 DB를 초기화하지 않는다.
명시 `activate-pg`는 검증한 복사본을 로컬 명령의 기본 대상으로 고정한다. 이는 기본 JAR의 PG 승격 및 전체
DB 전환 인수와 별개이며 선택/입력/기동 실패에 MySQL로 자동 복귀하지 않는다.
첫 선택은 writer 정지 창의 현재 MySQL/PG·승인 artifact 전행/7고수위 검수가 필요하며, PG 쓰기 뒤의
복구본 승계는 초기 cutover와 별도인 PG 백업/복구·promote로 검사한다.

DB05의 [Psycopg3 relay](SEARCH-RELAY.md)와 [공개 검색/필수조건 대체](PRODUCT-SEARCH.md)는
같은 source/target binding·기존 ACK·현재 DB 사실을 보존한다. JPA 공개 앱은 엔진/ACK를 쓰지 않는다.
필수 검증과 원본/자원 보존 정책은 [TESTING](TESTING.md)을 따른다.

기본 JAR에서 MySQL/MyBatis 런타임은 제외했다. 실제 DB 전환·콜레이션/전체 업무·웹 재인수·relay 운영·cutover 후 쓰기
역이관/rollback은 DB03–06의 남은 게이트다. TX/문장/실제시각과 잠금 의미를 이름만 보고 복사하지
않고 원본/과거 검증을 PG 성과로 바꾸지 않는다. UUID/ACK 초기화·재색인을 복구로 자동 실행하지 않는다.

DB06의 [명시 쓰기 정지 백업/새 PG 복구](LOCAL-DEVELOPMENT.md#쓰기-정지-postgresql-복사본의-백업새-대상-복구)는
import 이후 V7의23업무표(추천 피드백·비공개 notebook·계정 cart/receipt·내부 알림 포함)·Flyway/receipt·원문 JSON·epoch/source UUID/claim/ACK와 소비된7개 sequence를
보존한다. 기존 v1/v2 source artifact와 MySQL 원본은 수정하지 않는다. 복구 TX의 COMMIT 뒤 exact
검수에 실패하면 이미 commit되었을 수 있는 새 소유 대상을 격리하고 완료 표시를 하지 않는다.
기본 스택 전환·PG→MySQL 역이관·live/PITR/RPO0 완료로 확대하지 않는다.
